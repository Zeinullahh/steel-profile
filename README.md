# STEEL PROFILES

Русскоязычный статический сайт-каталог на Next.js App Router, React, TypeScript и Tailwind CSS. Все 19 товарных направлений и контакты загружаются из локального `CONTENT_DATA.json`. Изображения находятся в `public/images/`. База данных, API routes, Server Actions, CMS и серверная обработка форм не используются.

## Локальный запуск

Нужен Node.js 20.9 или новее и доступ к npm registry при первой установке.

```bash
npm install
npm run dev
```

Откройте `http://localhost:3000`. Для проверки релизной версии:

```bash
npm run lint
npm run verify:content
npm run build
```

Используется `output: "export"` в `next.config.ts`. Next.js создаёт статические файлы в `out/`, включая 19 товарных страниц из `generateStaticParams()`. Изображения оптимизированы как WebP в комплекте, а `next/image` обеспечивает размеры, lazy loading и предотвращение сдвигов макета; встроенный серверный оптимизатор отключён для статического экспорта. Шрифт Inter хранится в `public/fonts/`, отдаётся локально через `@font-face` с `font-display: swap`, основной файл предварительно загружается. [Лицензия Inter — SIL Open Font License](https://github.com/rsms/inter/blob/master/LICENSE.txt).

## Публикация на Vercel

1. Поместите проект в Git-репозиторий и импортируйте его в Vercel как Next.js проект.
2. Укажите переменную окружения `NEXT_PUBLIC_SITE_URL` с окончательным HTTPS-адресом сайта без завершающего слеша, например `https://example.com` (замените пример реальным доменом).
3. Запустите Deploy. Vercel установит зависимости и выполнит `npm run build`; отдельные сервер и база данных не нужны.
4. После публикации откройте главную, `/catalog`, `/solutions`, `/about`, `/contacts`, несколько прямых ссылок `/catalog/[slug]`, `/sitemap.xml` и `/robots.txt`. Проверьте работу поиска, фильтров и мобильного меню.

Без `NEXT_PUBLIC_SITE_URL` canonical URL не публикуется, а sitemap остаётся пустым: проект не подставляет выдуманный домен или `localhost` в SEO-разметку. Задайте переменную **до** production-сборки.

## Обновление каталога

- Товары, группы, варианты и контакты редактируются в `CONTENT_DATA.json`.
- У нового товара должен быть уникальный латинский `slug`, существующий `group` и путь к файлу в `public/images/`.
- Дополнительные изображения товарной страницы указаны в `src/lib/product-detail.ts`; добавляйте только изображения с подтверждённым соответствием товару.
- После изменения данных выполните `npm run build`: статические товарные страницы и sitemap генерируются заново.
- Контакты обновляйте в JSON; телефоны и почта автоматически отображаются на странице контактов и в подвале.

Не добавляйте неподтверждённые цены, остатки, гарантии, технические параметры и фотографии якобы выполненных компанией объектов.

## Проверки и ограничения текущей среды

`npm run verify:content` прошёл: проверены 19 уникальных slug, 5 групп, изображения и ссылки на товары из раздела «Решения». Отдельно проверены синтаксис 18 исходных TS/TSX файлов и CSS. В текущей рабочей среде `npm install` не завершился: соединение с npm registry заблокировано (`ECONNREFUSED 127.0.0.1:9`), а в офлайн-кэше отсутствует `@tailwindcss/postcss` (`ENOTCACHED`). Из-за отсутствия `node_modules` запуск `npm run build` завершился сообщением `next is not recognized`, а `npm run lint` не может загрузить `@eslint/eslintrc`. Поэтому production-сборка, полный lint, браузерная проверка ширин 320–1920 px и показатели Lighthouse **пока не подтверждены**. Их необходимо выполнить в среде с доступом к npm до публичного запуска.

Перед публичным релизом владелец компании должен подтвердить актуальность телефонов, адресов, e-mail, Instagram и разрешение на использование логотипа и знаков из предоставленного каталога.
