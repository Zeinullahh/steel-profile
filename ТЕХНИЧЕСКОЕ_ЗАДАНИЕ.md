# Техническое задание: корпоративный сайт-каталог STEEL PROFILES

**Версия:** 1.0 · **Язык сайта:** русский · **Источник контента:** «каталог в кривых (16 версия).pdf», каталог STEEL PROFILES 2026–2027 · **Результат:** готовый к деплою на Vercel статический сайт на Next.js.

> **Инструкция кодинговому агенту:** реализовать рабочий сайт, а не только макет. Использовать локальный контент и изображения из приложенного комплекта. Не добавлять базу данных, CMS, сервер, API, авторизацию, админ-панель и платные внешние сервисы. Если в PDF нет данных, не придумывать их. Передать рабочий исходный код с README и инструкцией по деплою.

## 1. Цель, продукт и границы проекта

**Бизнес-задача:** превратить печатный каталог STEEL PROFILES в современный корпоративный B2B/B2C-сайт-каталог, на котором посетитель быстро знакомится с направлениями, выбирает подходящую продукцию, смотрит реальные фотографии и характеристики из каталога и связывается с компанией для консультации или расчёта. Сайт **не интернет-магазин**: нет корзины, оплаты, личного кабинета, склада, расчёта цен в реальном времени.

**Целевые аудитории:** владельцы домов и участков; архитекторы и дизайнеры; строительные компании и подрядчики; управляющие компании и коммерческие заказчики. Не заявлять о конкретных клиентах, стройках, сертификатах или размерах бизнеса без подтверждения.

**Успешный итог:** быстро открываемый на телефоне, планшете и компьютере сайт с главной, каталогом, страницами продукции, разделом компании и контактами. Все страницы русскоязычные, изображения оптимизированы, кнопки и маршруты работают, сборка проходит в Vercel.

**Строгие ограничения:**

- Next.js (App Router) + React + TypeScript + Tailwind CSS; допустимы `lucide-react` для иконок и `framer-motion` (только при необходимости) для анимаций.
- Хостинг — Vercel; публикация из Git-репозитория через стандартный процесс Import Project → Deploy.
- **Без СУБД, ORM, CMS, серверной обработки заявок, API routes, Server Actions, внешнего хранилища, аутентификации, аналитических пикселей по умолчанию и сторонних платных интеграций.**
- Контент в типизированных локальных файлах (`src/data/*.ts` или JSON), изображения в `public/images/`; никаких обязательных запросов к внешнему API на клиенте и сервере.
- Страницы должны быть статически генерируемыми. Можно использовать `output: 'export'` в `next.config.ts` (с `images.unoptimized = true` для статического экспорта) либо обычную SSG-сборку Next.js для Vercel без серверных маршрутов; **выбрать один вариант, объяснить в README, не подключать SSR без необходимости**.
- Никаких автоматических публикаций «псевдоотзывов», выдуманных прайсов, фейковых акций или фейкового портфолио.

## 2. Источники правды, правила контента

В данном PDF **23 страницы**, из которых **физические страницы 2 и 22 являются пустыми**. Страницы PDF 3–21 соответствуют печатным страницам каталога 1–19. Обложка — PDF-стр. 1, контакты — PDF-стр. 23.

**Приоритет:** (1) PDF (для конкретных характеристик); (2) `CONTENT_DATA.json` (подготовленная структура и аккуратно переписанное содержание); (3) визуальные референсы в `design-reference/` — **только для вдохновения стилем**, тексты, адреса, факты или картинки продуктов из них не брать. Данные в JSON требуют финальной сверки владельцем перед публикацией.

**Из PDF доступны:** продуктовые направления, серии/модели, некоторые заявленные свойства и габариты, цветовые варианты, четыре преимущества из обложки и контакты. **Не предоставлены:** цены, точные товарные SKU для всех моделей, наличие, юридические реквизиты, подтверждённые фотографии реализованных объектов и измеримые результаты компании. Эти блоки пропускать, а не «заполнять для красоты». Не выдавать архитектурные иллюстрации из каталога за «выполненные проекты».

Технические заявления типа «срок службы более 50 лет» или габариты писать с контекстом «по данным каталога» и не распространять на все категории. Не предлагать скачивание оригинального PDF, если исходный 80 МБ-файл не был отдельно добавлен в релиз; при желании можно сделать ссылку на оптимизированную отдельную PDF-версию, **но это не обязательная функция**.

## 3. Информационная архитектура и карта сайта

**Шапка:** логотип слева; «Главная», «Каталог», «Решения», «О компании», «Контакты»; справа заметная кнопка «Связаться». На десктопе меню «Каталог» с 5 укрупнёнными группами. На мобильном — доступное выдвижное меню, закрывающееся по Escape/клику на пункт/вне области.

### Обязательные адреса

| URL | Страница | Назначение |
|---|---|---|
| `/` | Главная | Первый экран, преимущества, основные направления, примеры применения, CTA и контакты |
| `/catalog` | Каталог | Все товары/семейства; клиентский поиск и фильтры |
| `/catalog/[slug]` | Товарное направление | Детальная страница каждого из **19** направлений в `CONTENT_DATA.json`; слуги должны быть статически сгенерированы |
| `/solutions` | Решения | Подбор категорий по задачам без недоказанных кейсов: частный дом, фасад, кровля, участок, гараж, коммерческий объект |
| `/about` | О компании | Что делает STEEL PROFILES, направления, четыре преимущества с обложки, без выдуманных цифр |
| `/contacts` | Контакты | Астана, Алматы, телефоны, e-mail, Instagram и кликабельные переходы |
| `not-found` | 404 | Полезный возврат в каталог/на главную |

Примечание: категории в навигации — это **визуальные группы/фильтры**. Не обязательно делать дополнительные `/catalog/category/*`: достаточно пяти чипов/групп в каталоге, чтобы не раздуть объём страниц. Если дополнительные страницы появятся, они должны быть SSG и полезны для SEO, а не дублировать каталог.

### Основные группы каталога

1. **Фасады:** фасадные панели (PDF 3), линейные панели (4), алюминиевые кассеты (5), фасадная подсистема (6).
2. **Кровля и водосток:** металлочерепица (7), кровельные доборные элементы Como (8), водосточная система (9), дополнительные кровельные элементы/планки (10).
3. **Заборы и ограждения:** заборы жалюзи и варианты (11–14), стальной штакетник (15).
4. **Ворота:** DoorHan (16), гаражные ворота (17), промышленные ворота (18), системы ограждений и ворот (19).
5. **Изделия и аксессуары:** корзины под кондиционер (20), почтовые ящики (21).

19 подготовленных контентных единиц содержатся в `CONTENT_DATA.json`. В релизе их можно выводить как 19 страниц с одним универсальным шаблоном ProductDetail. Для групп с вложенными моделями сделать локальные блоки модификаций/вариантов.

## 4. Визуальный язык: glassmorphism, но пригодный для промышленного каталога

**Концепция:** технологичный «архитектурный премиум». Тёмно-синий и графитовый фон, электрические синие акценты (цвет STEEL PROFILES), большие качественные фотографии домов и металлоизделий. На фотографиях — полупрозрачные «стеклянные» блоки с размытием. Самые важные технические параметры — на контрастном сплошном фоне, чтобы не ухудшить читаемость.

**Дизайн-токены (предложения, не официальные RAL-коды производителя):**

```css
:root {
  --bg-0: #071421;
  --bg-1: #0b2136;
  --bg-2: #112e4d;
  --accent: #0969d8;
  --accent-hover: #2484f2;
  --text-primary: #f7faff;
  --text-secondary: #c5d5e8;
  --glass-bg: rgba(255,255,255,.09);
  --glass-stroke: rgba(255,255,255,.18);
  --glass-shadow: 0 14px 50px rgba(0,0,0,.22);
  --radius-card: 24px;
  --radius-control: 14px;
}
.glass {
  background: var(--glass-bg);
  border: 1px solid var(--glass-stroke);
  box-shadow: var(--glass-shadow);
  -webkit-backdrop-filter: blur(16px);
  backdrop-filter: blur(16px);
}
```

**Шрифт:** Manrope (или Inter) с поддержкой кириллицы, через `next/font` с локальной сборкой. Загрузка без внешнего запроса во время просмотра. H1 48–72 px на больших экранах / 34–42 px на телефонах; основной текст 16–18 px; таблицы характеристик 14–16 px. Не печатать всё caps lock: жирный заголовок из печатного каталога — бренд-референс, а не обязанность повторять верстку CorelDRAW.

**Палитра и «стекло»:** использовать полупрозрачность и blur **только на отдельных карточках, навигации, карточке первого экрана, информационных панелях**. Изображения продуктов должны оставаться чёткими, а их детали — видимыми. Не добавлять стеклянную заливку поверх мелких текстур панелей. Не использовать грандиозные фоновые видео, тяжёлые WebGL/3D-эффекты и гирлянды анимаций.

**Логотип:** `public/images/steel-profiles-logo-from-catalog.png` — вырезка официального знака из PDF с прозрачностью. Проверить видимость и качество в шапке на тёмном фоне; при необходимости использовать белую бренд-плашку, а не перерисовывать фирменный знак по памяти. Полноценный фирменный SVG можно заменить только если заказчик его предоставит.

**Движение:** появление секций при скролле (150–350 ms), hover-карточки (лёгкое смещение на 2–4 px), мягкий переход табов и меню. Учитывать `prefers-reduced-motion: reduce`; анимации не должны скрывать содержимое при отключённом JS.

**Сетка:** max-width 1280–1360 px, desktop 12 колонок, секции через 88–120 px, планшет 48–72 px, телефон 48–64 px. Минимальные кликабельные области — примерно 44×44 px. Не допускать горизонтального скролла на ширине 320 px.

**Визуальные референсы:** файлы `design-reference/ui-concept-generated-*.png` содержат пример сочетания фотографий архитектуры и glassmorphism. Это сгенерированные картинки, а не точные дизайнерские макеты; при расхождении с данным ТЗ приоритет у этого текста и PDF.

## 5. Структура и поведение ключевых страниц

### 5.1 Главная `/`

1. **Sticky Header**: логотип, разделы, CTA. Скролл-шапка с тёмным стеклянным фоном, при прокрутке уменьшить высоту, не прыгать по верстке.
2. **Hero** высотой 75–90vh на desktop (не ниже 600 px, но не делать текст невидимым на экранах 1366×768). Фон — **`hero-facade-house.webp`**, из PDF, с затемнением/градиентом слева. H1: «Комплексные решения для частных домов и коммерческих объектов». Подзаголовок: «Фасады, кровля, ограждения, ворота и элементы благоустройства». CTA1 «Смотреть каталог» → `/catalog`; CTA2 «Связаться» → `/contacts`.
3. **Четыре преимущества** — в одной стеклянной полосе или сетке: Надёжность, Эстетика, Простой монтаж, Гармония. Раскрывающие фразы из обложки можно мягко переформулировать; не добавлять неподтверждённые гарантии.
4. **Направления продукции** — пять крупных карточек групп (фасады, кровля, ограждения, ворота, аксессуары) с фотографией, названием, коротким описанием и ссылкой на фильтр каталога. На широком экране композиция 3+2, на мобильном — 1 колонка.
5. **Популярные решения** — 6 карточек ключевых направлений: фиброцементные фасадные панели, линейные панели, металлочерепица, заборы жалюзи, гаражные ворота, корзины под кондиционер. Слово «популярные» допустимо как рубрика без утверждения о фактических продажах; лучше название «Выбор для вашего проекта».
6. **Решения по задачам** — «Для частного дома», «Для фасада», «Для участка», «Для гаража», «Для коммерческого объекта»; переход в `/solutions` или каталог с фильтром.
7. **О компании** — короткий блок «STEEL PROFILES» и формулировка об ассортименте из каталога без годов основания, числа сотрудников и географии поставок, если таких фактов в PDF нет.
8. **Контактный CTA** — «Подберём решение для вашего проекта» и кнопки «Позвонить», «Написать на e-mail», «Контакты»; не обещать ответ за 5 минут.
9. **Footer**: логотип, 5 групп каталога, контакты, ссылки, © с динамическим годом (на клиенте или при сборке), без выдуманных реквизитов.

### 5.2 Каталог `/catalog`

- H1 «Каталог продукции», пояснение «Материалы для фасадов, кровли, ограждений и благоустройства».
- Панель поиска по названиям, ключевым словам, вариантам и описаниям. **Поиск только по локальному массиву** (`useMemo`), без обращений к серверу. Мгновенный результат, удаление запроса и пустое состояние «Ничего не найдено».
- Группировка/фильтр по пяти группам; можно добавить фильтры по назначению («дом», «коммерческий», «фасад», «ограждения») из `filterTags`. **Не делать фильтров по цене, наличию, рейтингу**, этих данных нет.
- Компонент `ProductCard`: соотношение фото 4:3 / 3:2, русское название, краткое описание, бейдж категории, ссылка «Подробнее»; никакой цены «от ...», если не задана.
- Desktop: 3 карточки в строке; tablet: 2; mobile: 1 (для широких телефонов можно 2, если читается). Skeleton не нужен, контент локальный.
- При переходе со страницы `/` с query `?group=facade`, `?group=roof` и т.д. корректно активировать фильтр на клиенте. Для статического экспорта проверить работу URL query на Vercel.
- На мобильном фильтры — горизонтальные чипы с возможностью прокрутки или компактный селектор, не огромный drawer без необходимости.

### 5.3 Детальная страница `/catalog/[slug]`

**Один универсальный шаблон для всех 19 позиций**, данные — из `CONTENT_DATA.json`, слуги передать в `generateStaticParams()`.

1. Breadcrumbs: Главная / Каталог / Наименование; JSON-LD BreadcrumbList при желании.
2. Название H1, небольшое описание, один крупный исходный снимок. Изображение `object-fit: contain` для вырезанных изделий; `cover` для архитектуры. Фото можно открыть в lightbox (клавиатура, Escape, закрытие, удержание фокуса).
3. Ключевые свойства 2–4 пункта — строго из локальных данных.
4. «Доступные варианты и покрытия» — **текстовые чипы/небольшие иллюстрации**, а не неподтверждённый селектор покупки. **Hex оттенков UI не считать официальными цветовыми кодами производителя**.
5. «Назначение и особенности» — абзацы из PDF, без искусственных цифр.
6. «Характеристики» — только подтверждённые (например, размеры ворот на стр.17); отсутствующие параметры **не показывать**. Не создавать универсальную таблицу со значением «уточняется» в 10 строк.
7. «Другие решения» — 3 карточки из той же группы, без дублирования текущего товара.
8. CTA «Уточнить характеристики» → e-mail / телефон / `/contacts`. В `mailto:` можно заранее заполнить тему (`Вопрос по: <название>`), но никакой фоновой отправки.
9. Для товарных категорий, где исходный PDF содержит больше модификаций, использовать секцию «Модели» с названиями из данных; фотографии конкретной модификации не подменять фото другой модели, если соответствие неизвестно.

**Особо важные семантические различия:**

- Фасады: фиброцементные панели ≠ линейные стальные панели ≠ алюминиевые/композитные кассеты ≠ подсистема крепления.
- Кровля: металлочерепица ≠ доборные элементы Como ≠ водосток ≠ общие кровельные планки.
- Ограждения: жалюзи ЭКО, жалюзи ТВИН, Планкен, Ранчо, евроштакетник и отдельный «стальной штакетник» не сливать в один товар.
- Ворота: DoorHan как отдельная марка, гаражные и промышленные секционные ворота, а также общие системы ограждений. Не представлять STEEL PROFILES производителем всех чужих брендов, если это не указано.
- Корзины под кондиционер и почтовые ящики — отдельные самостоятельные направления.

### 5.4 Решения `/solutions`

Представить как **подбор по применению**, не как «кейсы компании». Блоки: частный дом (кровля + фасад + забор + ворота), коммерческий фасад (кассеты + подсистема), участок и периметр (жалюзи/штакетник + ворота), гараж и склад (секционные промышленные ворота). Каждое решение содержит короткий текст, 2–4 товарные ссылки. Не приписывать объектам в каталоге адреса, стоимость или статус выполненного проекта.

### 5.5 О компании `/about`

Проверенный минимум: название STEEL PROFILES; позиционирование «современные системы ограждений и элементы благоустройства» (в PDF); представлены решения для частных домов и коммерческих объектов. Использовать визуальный блок из оригинальных фотографий. Четыре преимущества с обложки; пять групп ассортимента; CTA. Не делать отдельные разделы «история с 2007 года», «200+ сотрудников», «завод полного цикла», «партнёры по всему миру» без документального подтверждения.


При необходимости адаптировать layout каталога к современному шаблону `src/app/*`, но выбрать **один** стиль структуры, не дублировать `app` и `src/app`. `CONTENT_DATA.json` можно непосредственно импортировать в TypeScript или преобразовать в `src/data/catalog.ts`. Интерфейс товара: `slug`, `title`, `group`, `pdfPage`, `description`, `image`, `variants[]`, `highlights[]`, `filterTags[]`, опциональные поля; `price`, `sku`, `availability` не визуализировать при `null`.

**Статика и маршруты:** список `slug` при сборке известен. Для `[slug]` использовать `generateStaticParams()`, при неизвестном slug — 404. Для статического экспорта не использовать `cookies()`, `headers()`, `draftMode()`, SSR-динамику и server-only API.

**Фильтры:** локальное состояние React, `filter`, `search`, `resultCount`. Если используется query string, корректно обработать hydration/`Suspense` по требованиям выбранной версии Next.js. Никакой внешней поисковой системы и индексатора.

**Контентные изменения:** новый товар = одна запись в локальном массиве + подходящий файл изображения; затем commit/deploy. В README объяснить этот процесс на 5 строках.

## 9. Доступность, скорость, SEO и качество

### SEO

- Русский язык в `<html lang="ru">`, корректный `<title>` и `meta description` для главной, каталога и каждой товарной страницы.
- ЧПУ/slug латиницей, canonical URLs на выбранном финальном домене; если домен ещё не известен, вынести в `NEXT_PUBLIC_SITE_URL` с безопасным fallback для локальной разработки, не публиковать каноникал на `localhost`.
- `metadata` / Open Graph с локальным изображением. `sitemap.xml`, `robots.txt` и доступный 404.
- Семантическая структура: один H1 на страницу, иерархия H2/H3, `<nav>`, `<main>`, `<section>`, `<footer>`, `<figure>` там, где необходимо.
- `Organization` JSON-LD (только подтверждённые название, сайт, контакты), `BreadcrumbList` для товара; **не делать `Product` schema с ценой/наличием/рейтингом**, которых нет.
- Уникальные заголовки и описания для всех 19 карточек; не создавать множество SEO-страниц с дублированным текстом.

### Performance

- Ориентир Lighthouse mobile: Performance ≥ 90, Accessibility ≥ 90, Best Practices ≥ 90, SEO ≥ 90 (цель оптимизации, не гарантия на любой сети).
- Core Web Vitals: ориентир LCP ≤ 2,5 c, CLS ≤ 0,1, INP ≤ 200 ms на типичных устройствах; при измерениях сохранить результаты и конфигурацию.
- Минимизировать зависимости, не подключать слайдеры/анимационные библиотеки ради одного hover-эффекта, не грузить все изображения каталога в hero.
- Шрифты локально через Next. Изображения — WebP и явно заданные размеры. Code splitting по маршрутам; client components только там, где есть интерактивность.
- `prefers-reduced-motion`, адаптивность к `forced-colors` в разумных пределах, fallback `background-color` при отсутствии `backdrop-filter`.

### A11y и UX

- Контраст текста на стеклянных поверхностях не ниже уровня WCAG AA: обычный текст ≥ 4.5:1, крупный ≥ 3:1. Если фон пёстрый — увеличить непрозрачность стекла или тёмный градиент.
- Видимый `focus-visible`, клавиатурная навигация, aria-label для icon-only кнопок, предсказуемая логика меню.
- Вся информация о товарах доступна текстом, а не только рисунками/иконками. Никаких автопрокручивающихся каруселей, закрытых для клавиатуры.
- Корректные состояния пустого поиска, 404, пустых изображений, длинных названий, неверных slug.
- Русский текст без «рыбного» lorem ipsum и без английских системных элементов интерфейса.

## 10. Responsive и состояния компонентов

Проверить минимально на ширинах **320, 375/390, 768, 1024, 1440, 1920 px**. На мобильном hero имеет фон/градиент достаточной контрастности, H1 не вылезает, преимущества переносятся в 2×2 или вертикально, каталог без горизонтального скролла всей страницы. `position: sticky` не перекрывает заголовок после перехода по якорю. Меню, фильтры, lightbox, tooltip, кнопки, изображения работают без hover. На desktop проверить широкие карточки и разумную ширину строки текста.

**Состояния:** normal, hover, focus, active, disabled (если реально нужен), empty search, unknown page. Не строить faux-loading состояния для статически известного контента. Не показывать «на складе», если нет данных.
